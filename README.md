# Racio_1bot

Telegram-бот сигналів для бінарних опціонів (21 форекс-пара).

## Що змінено у версії 3 (мульти-ТФ + якість)

**Мета:** підняти реальний вінрейт і НЕ зменшити кількість сигналів.
Для цього потік розширено (більше незалежних джерел сигналів), а відсіюються лише
дублікати та сегменти, які статистично програють.

### Нові модулі
| Файл | Призначення |
|---|---|
| `timeframe_profiles.py` | Профілі 1m / 3m / 5m / 15m: робочий ТФ, підтверджуючий ТФ, діапазон експірації. Вмикаються через `ACTIVE_PROFILES`. |
| `signal_pipeline.py` | Генерує кандидатів по всіх профілях. Лише ЗАКРИТІ свічки, перевірка свіжості, ≥2 незалежні підтвердження, `bar_id` для дедуплікації. |
| `quality_gate.py` | `SignalGate` (дедуплікація, cooldown, конфлікт напрямків, ліміт експозиції по валюті) і `SegmentFilter` (блокує лише сегменти/години, де верхня межа Wilson-інтервалу < беззбитковості, мін. 40 угод). |

### Виправлено
* **ML**: ознаки тепер реально пишуться в БД (`save_signal`), навчання на рядках із ознаками, валідація на відкладеній вибірці (AUC ≥ 0.53), прибрано штучну підлогу `max(0.55, p)`. Якщо моделі нема — фільтр нейтральний і чесно про це каже. Додано ознаки `tf_minutes`, `confirmations`. Якщо `xgboost` не встановлено — використовується sklearn.
* **Сигнал на закритій свічці** (раніше last close підмінявся live-ціною → перемальовування). Ціна входу — live-ціна в момент відправки.
* **Yahoo-час**: `tz_localize(None)` зсував час; тепер конвертація в UTC.
* **Pivot-фільтр** раніше завжди повертав True; тепер блокує вхід, коли рівень впритул на шляху ціни.
* **VWAP** скидається щодня.
* **Подвійна обробка результатів**: атомарний `claim_signal` (PENDING → PROCESSING).
* **Бектест** переписано: реальні 1m-дані, ресемплінг, закриті свічки, експірація в хвилинах, ті самі фільтри, інтервал Wilson і беззбитковий рівень.
* **Gemini**: кеш списку моделей, експірація ШІ обмежена діапазоном ТФ.
* **Авто-сканер** прокидається на початку кожної хвилини, щоб ловити кожну закриту свічку.

### Нове в БД
`primary_tf` (ТФ сигналу), `score` (кількість підтверджень) тепер заповнюються. Старі записи без ознак у навчання ML не потрапляють.

### Налаштування
* Профілі та експірації: `timeframe_profiles.py` (`PROFILES`, `ACTIVE_PROFILES`, `min_confirmations`).
* Ліміти gate: `SignalGate(...)` у `bot.py` (cooldown, `max_ccy_exposure`, вікна).
* Поріг блокування сегментів: `SegmentFilter(break_even=..., min_trades=...)`.

### v3.1
* Активні профілі: **3m / 5m / 15m** (1m вимкнено); максимальний вік свічки для автоаналізу — **150 / 180 / 240 с**. Експірації: 3–6 / 5–15 / 15–30 хв.
* `TREND_IMPULSE`: глобальний тренд має збігатися з трендом підтверджуючого та старшого ТФ (EMA50). Після торкання EMA20/VWAP попередньою свічкою потрібна закрита свічка за трендом із поверненням за EMA20; межі RSI збережено.
* Глобальний тренд більше не рахується незалежним підтвердженням `TREND_IMPULSE`: замість нього перевіряється нахил EMA20 старшого ТФ.
* `RANGE_CORRIDOR`: базовий бал 2.4; вага відбоїв щонайменше 1.1 для всіх пар, 1.15 для мажорів і флетових пар із наявного списку.
* Pivot-рівні обчислюються з денних даних (за відсутності достатніх даних — із 1h).
* `SegmentFilter`: поріг беззбитковості **0.54**, мінімум **40 угод**.

### v4: стратегії відбою 5m
* Лише закриті 5m-свічки, вік ≤180 с, прогрів 200 барів. RSI — RMA (`ewm(alpha=1/n, min_periods=n)`, `adjust=True`); BB20 — population std (`ddof=0`).
* **REV_RSI14**: RSI14 <20 → CALL, >80 → PUT; фіксована експірація **60 хв**. Research holdout: **276 угод / 67.03%**.
* **REV_RSI7**: RSI7 <15 → CALL, >85 → PUT; фіксована експірація **45 хв**. Research holdout: **921 угода / 60.80%**.
* **REV_BB3**: close поза BB20 ±3σ та RSI14 <30 / >70; експірація **60 хв**. Research holdout: **351 угода / 65.24%**.
* Пріоритет на одному барі: REV_RSI14 → REV_BB3 → REV_RSI7. Без перекриття відкритих сигналів однієї пари/пресету (пам'ять + PENDING/PROCESSING у БД, також після рестарту).
* Для REV не застосовуються AI/ML, pivot-фільтр і підтвердження confluence; експірація не змінюється ШІ. Новини, SegmentFilter, свіжість, gate та захист від несприятливого руху ціни зберігаються.
* Три пресети мають окремі глобальні й попарні перемикачі, за замовчуванням ON. Для **нових** конфігурацій старі чотири confluence-стратегії OFF: їхній спільний бектест дав близько **49% (6619 угод / 49.09%)**. Наявні збережені налаштування не змінюються.
* `/backtest` враховує REV і показує розбивку за стратегіями. Для довгої 5m-історії: `backtest.simulate_reversion_pair(pair, df_5m, strategies_status=..., start=..., end=...)`; подайте історію **до** start для прогріву, а не обрізаний holdout.
* **Це лише research**, не гарантія живого вінрейту: 21 пара, часовий поділ 50/25/25, 5m holdout 20 жовтня–10 листопада 2026, лише 16 торгових денних кластерів, багато перевірених конфігурацій. Цифри вище — незалежні запуски кожного пресету, їх не можна додавати; пріоритет і живі фільтри змінюють спільний потік. Потрібен новий forward-test на цінах виконання брокера.

### Важливо
* Реальний вінрейт можна оцінити лише на живій статистиці БД (дашборд) і на бектесті; жодної гарантії 65–70% немає.
* Для виплати 85% беззбитковість ≈ 54.1%.
* Безкоштовні джерела (Yahoo 1m) мають затримку; ціни можуть відрізнятися від брокерських.
